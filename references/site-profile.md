# Site Profile

Load this reference only when missing project/site context can materially change the result.

## Gather context efficiently

If a connected site is available, inspect discoverable facts first. Ask only for facts that remain unknown and decision-relevant.

Potential inputs include:

| Input | Ask only when it changes |
|---|---|
| Site purpose / audience | information architecture, tone, conversion priority, or content hierarchy |
| Language and RTL/LTR | layout direction, icon placement, typography, or responsive behavior |
| Visual direction | composition, density, shape language, imagery, or interaction style |
| Brand colors/tokens | color system or component styling |
| Container model | full-width vs boxed behavior and section geometry |
| Page goal / CTA | hierarchy, section order, and conversion flow |
| Required content/sections | actual page structure |
| Reference sites/images | visual interpretation when text direction is insufficient |
| Plugin/theme constraints | implementation mechanism or compatibility |

Do not ask for every field. Skip anything already provided, safely discoverable, or irrelevant to the requested work.

## Preserve project-specific state

Treat project-specific colors, URLs, IDs, content, plugin choices, and brand rules as site context, not global Skill defaults. Never carry them into an unrelated site unless the user explicitly supplies them again as applicable context.
